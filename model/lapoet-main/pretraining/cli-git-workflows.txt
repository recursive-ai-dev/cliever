Git is a distributed version control system.
git status shows what changed in your working tree.
git add stages changes for the next commit.
git commit records staged changes with a message.
Use conventional commits for consistent history.
A clean working tree means no uncommitted changes.
A branch is a movable pointer to a commit.
Create a branch with git switch -c feature name.
Switch branches with git switch branchName.
Use git checkout only if you need older behavior.
git pull fetches and merges or rebases remote changes.
Prefer git pull --rebase to avoid merge commits in linear workflows.
Use git fetch to update remote tracking branches without merging.
Compare branches with git log main..feature.
See a diff with git diff.
See staged diff with git diff --staged.
Undo staging with git restore --staged file.
Undo working tree edits with git restore file.
Be careful, restore can discard changes.
Use git stash push to save work in progress.
Use git stash pop to reapply stashed work.
If you get conflicts, resolve then git add and continue.
A merge conflict happens when two changes touch the same lines.
Use git rebase --continue after resolving conflicts.
Use git merge --abort or git rebase --abort to stop a bad operation.
Use git log --oneline --graph to visualize history.
Use git blame file to see who last changed each line.
Use small commits that do one thing.
Write commit messages that explain why.
Use .gitignore to ignore build outputs and secrets.
Never commit API keys or tokens.
Use git remote -v to inspect remotes.
Use git tag to mark releases.
Use git tag -a v1.0.0 -m message for annotated tags.
Use git diff main...feature to compare with the merge base.
Use git cherry-pick to copy commits.
Use git revert to make a safe undo commit.
Prefer revert over reset on shared branches.
git reset --soft moves HEAD but keeps staged changes.
git reset --mixed keeps changes but unstages them.
git reset --hard discards changes, dangerous.
Use git clean -fd to remove untracked files, dangerous.
Use git worktree for multiple working directories.
A good workflow is branch, commit, open PR, review, merge.
Use pre-commit hooks to run formatting and linting.
If a file is large and changes often, consider LFS.
If a merge commit is unwanted, use squash merge.
If history matters, use rebase merge.
When in doubt, run git status again.
